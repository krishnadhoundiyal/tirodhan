## Execution Summary
The mandated QA tests cannot be executed in the current CI environment. The environment completely blocks Docker container execution, leading to failures when the test suite tries to spin up PostgreSQL, OSRM, or VROOM through `docker run`.

1. Running the `test_admission_native.py` file with the explicitly required `TIRODHAN_ROUTING_ENGINE_TESTS=1` configuration flag passed for `ORToolsOptimizer` since it was installed via pip (`ortools==9.14.6206`). However, the `VroomOptimizer` tests failed because `vroom` is not available in the `$PATH` and Docker is not functioning to provide the `vroom` binary as a service or executable.
2. The `run-regional.ps1` script (or attempting to run Docker containers manually) resulted in Docker failures: `docker: Error response from daemon: failed to mount ... fstype: overlay ... err: invalid argument`.
3. Since Docker execution is blocked, there is no way to start `postgis` for full end-to-end operational simulations, nor is it possible to use the `osrm-backend` Docker container required for the road network matrix generation.

## Findings

1. **Environment Failure: Missing Native Dependencies and Docker Mount Issues**
   - **Category:** Environment failure
   - **Severity:** P0
   - **Description:** The automated execution environment (sandbox) blocks Docker overlayfs mounts. Consequently, PostgreSQL/PostGIS, OSRM, and VROOM cannot be provisioned.
   - **Affected Business Rules:** The independent QA mandate cannot verify correctness rules due to the lack of infrastructure.
   - **Suggested Remediation:** The environment running these automated QA tasks must have Docker enabled and properly configured for `overlayfs` mounts, OR pre-install VROOM natively (e.g. from source) and provide a persistent database rather than ephemeral dockerized PostGIS.
